# OPC UA 插件 · 使用文档

本插件为 DBX 提供 **OPC UA 客户端读写能力**：连接 PLC / OPC UA 服务器，浏览地址空间，读取与写入节点值。本文面向使用方，介绍如何安装、连接与使用。

> 功能范围：**连接 + 地址空间浏览 + 读 + 写**。暂不支持订阅监控（Subscription）、方法调用（Call）、历史读数（HistoryRead）。安全策略仅支持 `None`（匿名或用户名 / 密码）。

## 支持平台

| 平台 | 架构 |
|------|------|
| Windows | x64 |
| Linux | x64 / ARM64 |
| macOS | Intel (x64) / Apple Silicon (arm64) |

每个平台提供独立的未签名开发包（`.dbxp`），需本机平台匹配方可安装。

## 安装与加载

1. 在 DBX 插件中心开启「允许安装未签名开发包」。
2. 安装对应平台的 `io.github.bobocha214.opcua-<版本>-<平台>.dbxp`。
3. 安装后在连接列表中出现 **OPC UA** 连接类型。

> 插件身份：`io.github.bobocha214.opcua`，发布者 `bobocha214`，许可证 **MIT**。

## 建立连接

在 DBX 连接管理中新增 OPC UA 连接，填写以下字段：

| 字段 | 说明 |
|------|------|
| 连接名称 | 显示名，自定义 |
| 主机 | OPC UA 服务器地址，如 `192.168.0.10` |
| 端口 | 默认 `4840` |
| 用户名 | 可选，留空为匿名 |
| 密码 | 可选，按敏感字段存储 |

连接凭据由 DBX 负责保存与生命周期管理，插件不直接接触明文密码。

## 三栏工作台

打开连接后进入 OPC UA 浏览器工作台，界面分为三栏：

- **左 · 地址空间树**：默认宽 236px，加载 `Objects` / `Types` / `Views` 三个标准根，按需向前展开。
- **中 · 点位区**：拖入变量后持续观察、就地改值下发。
- **右 · 点位详情**：展示选中点位的 NodeId / BrowseName / DisplayName / NodeClass、当前值、写入表单。

### 调整栏宽

- 拖动两条分隔条即可改变左 / 中 / 右栏宽。
- 键盘聚焦分隔条后，`←` / `→` 微调，`Shift` 加速。
- 双击分隔条恢复默认 236 / 302。
- 宽度按面板记忆在本地，面板过窄时中间点位区保底 200px。

## 监视点位

1. 从左侧地址空间树中，把 **Variable** 节点拖到中间点位区即加入监视。
   - 拖入 `Object` / `Method` 等非变量节点会被拒绝并提示原因。
   - 也可在树上悬停 Variable 行点「＋」，或在右侧详情点「加入点位区」。
2. 点击「▶ 持续观察」，按 200ms / 500ms / 1s / 2s / 5s 间隔轮询。
   - 采用 **`opcua/readMany` 批量读**，N 个点只花一次往返。
   - 上一轮未返回时自动跳过本轮，避免请求堆积。
3. 轮询失败会停止观察并提示（常见原因：会话未建立，需先在 DBX 中打开该连接）。

## 就地改值下发

- 点击数值单元格 → 变为已全选的输入框 → 改完回车（或失焦）即 `opcua/write` 下发，`Esc` 取消。
- 写入成功后自动回读该点，单元格**绿色闪烁**；失败**红色闪烁**并显示服务器返回的状态码与原因。
- 轮询期间**不会覆盖你正在编辑的单元格**。
- 点位按连接记忆在本地，切换连接后自动恢复；`×` 移除单点，「清空」全清。

## 数据类型与写入规则

写入类型由 **服务器事实** 决定，而非本地猜测：

1. 写入前先读取节点的 `DataType`（14）、`ValueRank`（15）、`UserAccessLevel`（18）。
2. `ValueRank` 为数组 / 多维数组时直接报错（仅支持标量写入）。
3. UI 默认 **Auto**：自动采用服务器 `DataType`。手动指定类型仅在服务器类型为抽象 / 自定义结构时生效；与服务器不一致会得到 `BadTypeMismatch`。
4. 值解析宽容：
   - 布尔：`true/false`、`1/0`、`yes/no`、`on/off`
   - 数字：允许前后空格、单个小数逗号（`1,5`）、JSON 数字（`12.5`）；越界会说明越界方向（超过上限 / 低于下限）
5. 只有 `Good` 系列状态码才判定为成功；`BadNotWritable` / `BadUserAccessDenied` / `BadOutOfRange` 等均判定失败，并附中文原因。
6. 写入成功后立即回读：若值未变化（只读点、被 PLC 程序覆盖、服务器忽略），会显式提示，而不是假装成功。

## 常见问题

### 下拉框里出现其他协议的连接（如 Modbus）

连接列表返回的是所有插件的脱敏连接（仅含 `id`、`providerId`、`name`、`label`，不含协议类型）。本插件按 `providerId` / 类型字段是否包含 `opcua` 识别自身连接；识别不到时**不会自动选中任何连接**，只提示「未发现 OPC UA 连接」。非 OPC UA 连接会带 `⚠ 非 OPC UA ·` 前缀，手动选中时再次警告。

### 从 v0.1.0 升级

v0.2.0 起插件 id 变更为 `io.github.bobocha214.opcua`（原 `io.github.yuzhi.opcua`）且许可证改为 MIT。**旧版本的已保存连接不会被迁移**，请在升级后删除旧连接、重新添加。

### 写入返回 BadNotConnected

连接尚未完成安全通道握手即发出请求会概率性失败。连接建立后会等待握手真正完成再返回；若仍出现，请先在 DBX 中打开该连接以触发会话建立，再试。

### 写入被判定为只读 / 失败

检查服务器返回的 `statusCode`：
- `BadNotWritable`：节点不可写
- `BadUserAccessLevel` / `BadUserAccessDenied`：当前用户无写入权限
- `BadOutOfRange`：值超出范围（提示会说明超出上限还是下限）
- `BadTypeMismatch`：类型不匹配，确认使用 Auto 或正确的数据类型
